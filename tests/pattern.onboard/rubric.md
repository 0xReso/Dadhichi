# Repository onboarding checks

| Check | Pass condition |
| --- | --- |
| Scope | Names the supplied boundary and unit. Four exclusive statuses reconcile to the known total. Any unknown remainder stays unknown. |
| Grounding | Each behavioral claim can be located in a supplied file or fragment. Conflicting sources are identified and the guide explains what each supports. |
| Model | Every edge has a meaningful relationship supported by the material or explicitly marked as an inference. A graph has a text equivalent. |
| Trace | One concrete input reaches the correct output or the guide identifies the exact evidence gap. Any described branch agrees with the source. |
| Navigation | A reader can open the named first stop and answer the guide's question there. The route addresses the supplied role and task when given. |
| First change | Locates an edit and an observable check, distinguishes suggested verification from existing tests, or identifies what missing file would enable either. |
| Exceptions | Identifies each fixture's consequential exception when present, such as integer truncation, stale limits, the broken sample or the inactive row. |
| Budget | Meets an explicit word ceiling. The tiny library stays under 250 words. Repeated generated or vendor entries appear as a counted group. |
| Limits | Never invents file bodies, run results, credentials, or unavailable behavior. For a tree alone it requests specific contents needed to continue. |
